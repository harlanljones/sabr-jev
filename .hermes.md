# Hermes session conduct — sabr-jev

Layered on `AGENTS.md` (which carries the repo's invariants and PRD
boundaries). This file is about how a Hermes agent behaves in this repo.

## Session behavior

- Start from `./dev` (repo root) so the `sabr-jev` profile, pruned skills,
  and hooks are active. `./dev setup` bootstraps; `./dev doctor` verifies.
- The PRD at `docs/specs/PRD-sabr-jev.md` is a CONDITIONAL APPROVE — treat
  its falsifier list as hard constraints, not suggestions.

## Hooks

| Hook | Event | Behavior |
|---|---|---|
| `sabr-jev-git-guard.sh` | pre_tool_call (terminal/execute_code, fail_closed) | Blocks mutating git (push/commit/checkout/…). Run git writes yourself or ask Harlan. |
| `sabr-jev-formatter.sh` | post_tool_call (write_file/patch) | `mix format` on edited `.ex/.exs`; no-op until mix + mix.exs exist. |
| `sabr-jev-evidence.sh` | post_tool_call (terminal) | Appends command evidence to `~/.hermes/agent-hooks/sabr-jev-evidence.jsonl`. |
| `sabr-jev-inject-git-status.sh` | pre_llm_call | Injects repo/branch/status when cwd is inside this repo (origin match: `sabr-jev`). |

A hook returning `{}` can mean wrong-match, not pass — if a guard seems not
to fire, smoke-test it with a real JSON payload on stdin.
